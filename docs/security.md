# Доступ и безопасность

Вход, сессии, ограничения и журнал аудита.

## Аутентификация и безопасность

Браузер входит по сессии, скрипты - по Basic Auth. Основной администратор
задаётся в файле окружения:

```text
CONAN_MANAGER_ADMIN_USERNAME
CONAN_MANAGER_ADMIN_PASSWORD
```

Дополнительных администраторов добавляют на странице «Панель»
(`GET/POST /api/v1/admins`, `PUT /api/v1/admins/{name}/password`,
`DELETE /api/v1/admins/{name}`). Их пароли хранятся в SQLite как
PBKDF2-SHA256 (210 000 итераций, соль 16 байт), не короче 10 символов.
Проверенный вход кешируется в памяти на 10 минут, чтобы не хешировать каждый
запрос; смена пароля или удаление сбрасывает кеш. Основного администратора
панель не показывает для удаления и не меняет.

### Вход и сессии

`POST /api/v1/login` `{username, password, remember}` проверяет пароль и
ставит cookie сессии; ответ содержит `csrf`. Сессия живёт в SQLite (переживает
перезапуск менеджера), в базе хранится только SHA-256 от токена. Любой
изменяющий запрос с cookie должен нести заголовок `X-CSRF-Token`, иначе 403:
чужой сайт может заставить браузер отправить cookie, но не может прочитать
токен. Без «Запомнить» cookie живёт до закрытия браузера.

- выход по бездействию - `CONAN_MANAGER_SESSION_IDLE` (12h, меняется и в
  панели; 0 - не выходить), предельный срок - `CONAN_MANAGER_SESSION_MAX_AGE`
  (168h);
- смена пароля или удаление администратора сразу завершает все его сессии
  (при смене своего пароля текущая сессия выдаётся заново);
- `GET /api/v1/sessions`, `DELETE /api/v1/sessions/{id}`,
  `POST /api/v1/sessions/end-others`, `POST /api/v1/logout`;
- `GET /api/v1/me` возвращает логин и `csrf` текущей сессии.

Basic Auth (`curl -u`) остаётся для скриптов и не требует CSRF-токена: браузер
не отправляет его сам, потому что менеджер никогда не просит его заголовком
`WWW-Authenticate`. Выключается `CONAN_MANAGER_BASIC_AUTH=false`.

### Ограничения попыток и частоты

После 10 неудачных входов (форма или Basic Auth) за 15 минут адрес
блокируется на 15 минут: ответ 429 с `Retry-After`, даже с верным паролем.
Блокируется адрес, а не логин, чтобы никто не мог запереть администратора,
подбирая его имя. Хеширование паролей ограничено двумя одновременно. Весь API
ограничен 20 запросами в секунду с запасом 200 на адрес.

### Адреса, прокси и HTTPS

Эти настройки задаются только в файле окружения: вход в панель не должен
позволять расширить доступ к ней.

- `CONAN_MANAGER_ALLOWED_IPS` - адреса и сети через запятую или пробел
  (`203.0.113.10, 192.168.1.0/24, 2001:db8::/32`); остальным - 403, включая
  страницу входа. Пусто - все адреса. Ошибка в списке не даёт менеджеру
  запуститься, а не открывает его.
- `CONAN_MANAGER_TRUSTED_PROXIES` - reverse proxy, чьим `X-Forwarded-For` и
  `X-Forwarded-Proto` менеджер верит. Клиентом считается правый адрес цепочки,
  который не является доверенным прокси, так что приписанные клиентом адреса
  ничего не дают. Без этой настройки заголовки игнорируются.
- `CONAN_MANAGER_TLS_CERT` и `CONAN_MANAGER_TLS_KEY` - HTTPS в самом
  менеджере (TLS 1.2+).
- `CONAN_MANAGER_ALLOWED_ORIGIN` - публичный адрес за прокси.

Рекомендуемая схема: менеджер слушает `127.0.0.1:8080`, перед ним nginx или
Caddy с сертификатом - готовые примеры в
[deploy/nginx-conan-manager.conf.example](deploy/nginx-conan-manager.conf.example)
и [deploy/Caddyfile.example](deploy/Caddyfile.example). По HTTPS добавляется
`Strict-Transport-Security`.

### Журнал аудита

Каждый изменяющий запрос к API пишется в таблицу `audit_log`: время,
администратор, адрес клиента, действие (`POST /servers/{}/start`), объект,
HTTP-статус результата. Туда же - входы, выходы, неудачные входы и
блокировки. Тела запросов не сохраняются (в них пароли и вебхуки): для
настроек пишутся имена изменённых полей, для RCON - команда. Хранится год, не
больше 100 000 записей. `GET /api/v1/audit?user=&target=&failed=1&before=&limit=`.
Результат длинных операций (установка, восстановление) - в истории событий.

### Проверка безопасности

Страница «Панель» показывает самопроверку (`GET /api/v1/security`): права и
владельца файла окружения, права базы и папок данных и бэкапов, ключ
шифрования и пароль основного администратора из примера, открытый наружу HTTP
без TLS, отсутствие allowlist, включённый Basic Auth. Менеджер сам ставит базе
права 0600 при каждом запуске, служба работает с `UMask=0027`.

`/healthz` и сама страница (без данных) доступны без входа.

Если нет ни основного администратора, ни добавленных, management API
блокируется с HTTP 503 (fail closed); это предотвращает случайный запуск API
без защиты.

### Настройки менеджера из панели

Часть переменных окружения можно переопределить на странице «Панель»
(`GET/PUT /api/v1/panel/settings`, `null` сбрасывает к файлу окружения).
Значение из панели главнее файла. Прокси уведомлений применяется сразу,
остальное - после перезапуска менеджера (`POST /api/v1/panel/restart`:
менеджер завершается с кодом 75, и systemd поднимает его по
`Restart=on-failure`; серверы-юниты продолжают работать).

Из панели меняются: `NOTIFY_PROXY`, `BACKUP_DIR`, `BACKUP_KEEP`,
`BACKUP_RETENTION`, `STOP_TIMEOUT`, `UPDATE_CHECK_INTERVAL`, `HOOK_TIMEOUT`,
`QUERY_INTERVAL`, `QUERY_TIMEOUT`, `QUERY_STARTUP_GRACE`,
`QUERY_UNAVAILABLE_FOR`, `ALLOWED_ORIGIN`, `EXPOSE_ERROR_DETAIL`. Только в
файле окружения остаются адрес и база, основной администратор, ключ
шифрования, `SERVER_UNITS`, `UNIT_DIR` и `HOOKS_DIR`: иначе украденный вход в
панель позволил бы, например, направить менеджер на папку со своими
скриптами. Для запросов с
заголовком `Origin` изменяющие методы принимают только same-origin запросы.
Также устанавливаются базовые security-заголовки и ограничивается размер POST body
до 1 MiB.
Если API работает за reverse proxy, публичный origin можно явно указать через
`CONAN_MANAGER_ALLOWED_ORIGIN`.

Перед доступом из интернета: HTTPS (прокси или TLS менеджера), файл окружения
`root:root 0600`, длинный пароль и ключ, по возможности
`CONAN_MANAGER_ALLOWED_IPS`. Секреты менеджера (вебхуки, токены, заголовки,
пароль прокси) уходят во frontend только замаскированными; пароли в INI-файлах
игры (RCON, сервер) видны в редакторе конфигов любому администратору.
